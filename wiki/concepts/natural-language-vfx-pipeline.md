# 자연어 기반 VFX 파이프라인

디자이너의 직관과 수십 개 파라미터 조정에 의존하는 기존 VFX 워크플로우를, 자연어 문장 하나로 대체하는 패러다임.

## 문제 정의

### 기존 방식의 문제
1. **디자이너 직관 의존 → 품질 편차**: 인디 디자이너는 검기 하나를 만들기 위해 수십 개의 파라미터를 감각으로 찍으며 시행착오. 같은 의도를 입력해도 경험에 따라 결과가 달라짐.
2. **저사양 호환 문제**: 대규모 스튜디오의 VFX 솔루션은 인디의 타깃 환경(중저사양 PC)에 도달하지 못함. 런타임 시뮬레이션은 GPU 부하 초과.

### Mythrill의 접근
두 문제를 **하나의 워크플로우 안에서 동시에 해결**:
- 자연어 인터페이스로 디자이너 직관 의존 제거
- 사전 베이크로 저사양 호환 확보

## 자연어 → 물리 매핑 과정

1. 디자이너가 자연어로 VFX 의도 입력 (예: "붉고 무겁게 흘러내리다 굳는 검기")
2. LLM ①이 의도를 파싱하여 단계 분리·현실 물질 후보 매칭
3. 사용자 확인 후 LLM ②가 적합한 솔버와 SI 단위 파라미터 결정
4. 물리 시뮬레이션 실행
5. 시각 오버레이 적용
6. 최종 결과 베이킹

## 차별점

- **자연어 VFX 도구만 있는 사례** (Unity Muse 등): 차별점 부족
- **물리 정합성만 강조**: 학술 영역, 게임 도구로 안 옮겨짐
- **베이크 파이프라인만**: Houdini가 표준, 인디 진입 장벽 높음

Mythrill의 차별점은 **셋의 교집합**: "기계공학 기반 물리 정합성 + 자연어 인터페이스 + 베이크 워크플로우".

## "왜 업계가 이 영역을 비워뒀는가"

1. **인력풀 문제**: 기계공학(유체역학) + 게임 VFX + AI 활용을 셋 다 아는 사람이 거의 없음
2. **타이밍 문제**: LLM 함수호출 정확도가 최근 2년 수준이 되어야 가능
3. **시장 인식 변화**: 인디 게임 시장 폭발 (스팀 출시 게임 수 매년 30% 증가)
