### 2. Researcher 토론 프로토콜 (토론형 cross-review)

- Round 0: 검증 가능한 명제 1~3개 분해

- Round 2: 교차 반박
- Round 3: 재반박/수정
- 최대 3라운드 하드캡, 합의 명제만 wiki에 기록

### 3. Wiki-First + Session-Search 강제

모든 역할군은 작업 시:

1. **wiki 먼저 검색** (~/.hermes/wiki/, graphify query)
2. wiki에 없거나 저장된 세션 내용이 자연스럽게 이어지지 않으면 → **session_search로 이전 대화 탐색**
3. 그래도 없으면 추측 금지, Director가 researcher 토론 요청
4. 합의 후 wiki 업데이트, 해당 페이지 읽고 작업 재개
5. 추측·환각으로 진행하면 작업 폐기

### 4. Cost Tiers (능력 기반)

[[cost-tiers]] 참조. 모델 이름이 아니라 **능력**으로 분류, 후보 풀만 갱신.

- Tier 1 — Frontier reasoning (Opus 4.7, Sonnet 4.6, GPT-5.5, Gemini 2.x Pro, DeepSeek V4-Pro)
- Tier 2 — Strong but cost-aware
- Tier 3 — Local open-weight (RTX 5090 도착 후)
- Tier 4 — Non-LLM automation

Sonnet/Opus 강화 버전 출시 시 즉시 교체 + 하네스 프롬프트도 [[model-prompting-conventions]] 따라 갱신.

### 5. Validator 패턴

별도 LLM 슬롯 아님. 검증 필요 시 가용 LLM이 즉석 스크립트 생성·실행·결과 보고. 의미 검증 = Frontier/Strong tier, 단순 회귀 = 로컬/스크립트.

## 다음에 할 것 (다음 세션 진입점)

### 즉시 착수 — Researcher Debate 하네스 구현

위치: `~/.hermes/skills/autonomous-ai-agents/researcher-debate/scripts/`

#### 모드: 하이브리드

- **A 경로 (subprocess)**: `hermes chat -q "<prompt>" -m <model> --provider <p>` 으로 외부 호출도 가능. cron·CLI에서 사용.
- **B 경로 (delegate_task)**: orchestrator(Director) 세션 안에서 `delegate_task`로 호출. Hermes 토큰·세션 관리 통합.
- 둘 다 지원, 호출자가 선택.

#### 구성

1. `debate.py` — 토론 진행기
   - 입력: 명제 + 컨텍스트
   - Round 1: 두 researcher 동시 독립 답변 (출처 필수, 없으면 폐기)
   - Round 2: 교차 반박
   - Round 3: 재반박/수정 (최대 3라운드 하드캡)
   - 출력: JSON `{agreed:[...], unresolved:[...], sources:[...], rounds:[...]}`

2. `write_to_wiki.py` — 합의 결과를 `~/.hermes/wiki/research/<slug>.md` 로 기록 + git commit/push + graphify 증분 갱신

3. `orchestrate.py` — 사용자 요구 → 계획 + 지식 갭 추출 → 갭마다 debate.py → wiki 누적

4. `SKILL.md` 갱신 — 하네스 사용법 추가

#### 호출 경로 정합성

- Researcher A (Sonnet 4.6): `hermes chat ... -m claude-sonnet-4-6 --provider anthropic` 또는 profile=researcher
- Researcher B (DeepSeek V4-Pro): OpenAI 호환 API 직접 호출 (DEEPSEEK_API_KEY/BASE_URL .env에 있음)
- Tech Artist (별도 DeepSeek 세션): debate.py에서 같은 키 다른 시스템 프롬프트

#### 시범 토론 주제 (검증용)

작은 명제 1개로 동작 검증. 예: "MPM 솔버에서 액체→고체 상전이 시 구성방정식 교체 시점을 어떻게 정의하는가" 같이 [[mythrill-spike-02]] 진입에 필요한 기술 명제. wiki에 이미 단편 정보가 있으니 토론 결과가 그 위에 누적되는 패턴이 자연스러움.
