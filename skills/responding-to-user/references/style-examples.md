# Response Style — Good vs Bad Examples

세션에서 실제로 발생한 사례 기반.

## Case 1 — "Mythrill 50 프롬프트 테스트 결과랑 분석 보내줘"

### ❌ Bad (사용자가 즉시 지적함)

> [1/2] LLM ① 50입력 검증 — 결과 (raw)
>
> v1 결과 (초기 라벨, 50×3=150 호출)
>   /Users/main/mythrill-pipeline/tests/results/v1/validation_20260502_182604.csv
>
> v2 결과 (...)
>   /Users/main/mythrill-pipeline/tests/results/validation_20260502_212822.csv
> ...

문제: 경로만 나열. 사용자는 즉시 "내가 정보를 달라고 하면 출처를 달라는게 아니라 내용을 출력해달라는거야. 출처만 주면 나보고 확인하라고? 내가 정보를 달라했는데 그건 좀 아니지 않아?" 라고 reject.

### ✅ Good

CSV/스크립트를 직접 읽고 본문을 인라인:

- 입력 50건 텍스트 그대로 (#1~#50).
- 모델별 스키마 적합도 수치 (49/50, 49/50, 50/50).
- 카테고리별 단계 정확도 v1 라벨 / v3 라벨 두 표를 컬럼 정렬해서 같이 출력.
- 모델 간 일치도 (39/10/1 = 78%/20%/2%).
- 라벨 재정렬 9건 표.
- 불일치 9건 상세.
- 마지막에 raw가 4000+줄이라 채팅 인라인이 무리임을 알리고 "패키지 폴더에 묶어줄까?" 명시적 옵션 제공.

핵심: **분석 스크립트를 실제로 실행해서 산출표를 가져왔다.** 메모리에서 회상하지 않고 디스크의 사실을 검증.

## Case 2 — 이전 세션 중단 지점 복원

### ❌ Bad

긴 마크다운 헤더 + 이모지로 답변 → CLI에서 깨짐.

### ✅ Good

`═══` 구분선, 인덴트 들여쓰기, 단순 콜론 정렬. 모든 결정사항을 bullet 한 줄씩.

## Format primitives 사용법

- 큰 섹션 구분: `═══════════════════════════════════════`
- 중간 섹션 구분: `▣ 섹션명`
- 항목 들여쓰기: 2-space + `•` 또는 그냥 들여쓰기
- 표: 고정폭 컬럼 정렬, 가독성 우선. 마크다운 `|` 표는 CLI에서 비추.
- 강조: 한국어 따옴표 「」 또는 백틱. `**bold**` 금지 (CLI에서 별표 그대로 노출).

## Raw 데이터가 큰 경우 결정 트리

1. 한 메시지 안에 들어가나? → 그대로 인라인.
2. 안 들어가면 → 핵심 통계 + 대표 N건 인라인 + "패키지로 묶어줄까?" 질문.
3. 절대 → "파일이 커서 못 보여드립니다" 단독 메시지 X.

## Case 3 — 검증 결과 → 핸드오프 문서 패키징 (2026-05-06)

사용자 흐름: "결과·분석 보내줘" → (스킬 로드된 상태에서도 첫 턴 출처-only 위반 → 사용자 정정) → 본문 인라인 → "문서로 만들어서 열어줘" → "출처 제거하고 그래프로 비교 가능한 건 그래프로" → "docs로, 안 되면 PDF".

### 학습된 규칙

1. **첫 턴부터 본문**. 스킬이 로드돼도 자동 발동 안 되면 의식적으로 적용. "정보 줘" 트리거 보면 무조건 1차 자료 read → 표·본문 인라인.
2. **외부 핸드오프 산출물 = 문서 + 그래프 + 변환된 포맷**. 단순 md 파일로는 부족. 분석 스크립트 재실행 → md → matplotlib PNG → pandoc docx 풀 체인이 디폴트.
3. **출처/내부 경로는 외부 핸드오프 시 제거.** 이번 사용자 명시: "출처 제거 버전". 외부 수신자에게는 raw 경로·위키 SoT 경로를 노출하지 않는다. 내부용은 부록 한 줄, 외부용은 통째로 제거.
4. **"비교"는 자동으로 그래프**. v1 vs v3, 모델별, 카테고리별 — 사용자가 명시 안 해도 그래프 같이.
5. **변환 폴백 명시**. "docs 안 되면 PDF" 같은 사용자 지시는 우선순위 명령으로 받고, 첫 시도 결과 보고 시 폴백 단계 사용 여부 같이 보고.

### 산출 디렉터리 패턴

```
<project>/docs/handoff/
  <topic>-handoff.md       # 마스터 본문
  <topic>-handoff.docx     # pandoc 변환본 (외부 전달용)
  figures/
    fig1_*.png
    fig2_*.png
    ...
```

자세한 빌드 절차는 `analytical-handoff-document` 스킬 참조.

## Case 4 — 단일 명령 산출물에 6섹션 매뉴얼 (2026-05-07)

흐름: 사용자가 PIL 합성 스크립트 산출물 사용을 원함 → AI가 응답에 "경로 / 사용법 / 옵션 / 구성요소 / 의존성 / 폰트" 6개 라벨된 섹션을 풀로 펼침 → 사용자 "경로, 사용법, 옵션, 구성요소, 의존성, 폰트 이걸 한번에 복사해서 붙이라고?" 라고 좌절.

### ❌ Bad

```
경로
   /Users/.../ai_rookie_hero.py

사용법
   python ~/.hermes/scripts/ai_rookie_hero.py \
       --prompt "..." \
       --asset /path/to/asset.png \
       --out /path/to/hero.png

옵션
   --ratio 21:9   기본값. 영화감 있는 와이드.
   --ratio 16:9   슬라이드 호환 필요할 때
   --model "..."   좌측 하단 메타 라벨
   --frame "..."   우측 하단 메타

구성 요소
   좌(36%): 라벨 INPUT - NATURAL LANGUAGE PROMPT, ...
   중앙: 시안→앰버 그라디언트 화살표 + ...
   우(60%): 에셋 cover-fit 풀블리드, ...
   배경 #0A0E1A, 미세 vignette ...

의존성
   pip install pillow

폰트
   /Library/Fonts/JetBrainsMono-Medium.ttf 와 ...
   brew install --cask font-jetbrains-mono font-inter

에셋 준비되면 위 명령 한 줄로 PNG 떨어집니다.
```

### ✅ Good

```
한 줄만 복사하시면 됩니다.

python ~/.hermes/scripts/ai_rookie_hero.py --prompt "..." --asset /경로/에셋.png --out ~/Desktop/hero.png

--asset 경로만 본인 이미지로 바꾸면 끝. 결과물은 ~/Desktop/hero.png 로 떨어집니다.

Pillow 없으면 먼저 한 번:
pip install pillow
```

### 학습된 규칙

1. 사용자가 "쓰고 싶은 도구"를 받았을 때 first-screen은 **복붙 가능한 한 줄** + **무엇을 바꿔야 하는지 1포인트** + **선결 조건 1줄**. 이 3줄이 끝.
2. 옵션·내부 구성·폰트·디자인 토큰·아키텍처는 사용자가 묻거나 미세조정 단계에 진입했을 때 펼침. 첫 응답에 절대 펼치지 않음.
3. 라벨된 섹션 6개 = 매뉴얼 모드 신호. 매뉴얼은 README나 references/에 가야지 turn 응답에 들어가면 안 됨.

## Case 5 — 모호한 요청을 한 방향으로 단정 (2026-05-07)

흐름: 사용자 "[Prompt → Generated Asset Image] 임팩트 있게 어떻게 보여줄까" → AI 4가지 옵션 제시 → 사용자 "단일 이미지" → AI 4가지 레이아웃 제시 → 사용자 "AI rookie 제출용" → AI 합성 **스크립트** 작성 + Pillow 설치법 → 사용자 "근데 이미지가 없어서 그걸 만든다는 거였는데? 예시 모습을?" 정정.

### 핵심 함정

산출물 형태가 두 갈래로 갈리는데 confirm 없이 한 쪽으로 진행:
- (A) 사용자 자체 에셋이 있다고 가정하고 합성 도구만 제공
- (B) 에셋이 없다고 가정하고 placeholder 포함 1장 미리보기 합성

이번엔 (B)가 정답이었지만 (A)로 갔다가 헛수고. 사용자도 첫 메시지에 "이미지 없음"을 명시 안 했어서 양쪽 다 합리적이었음 — 그래서 confirm 1줄이 정답.

### 학습된 규칙

1. "X 만들어줘 / 보여줘" 류 요청에서 산출물이 (a) 도구·코드·스크립트 (b) 실제 산출물 한 장 두 갈래로 갈릴 수 있으면 첫 턴에 1줄 confirm: "도구만 만들어드릴까요, 아니면 예시 1장 바로 떨궈드릴까요?"
2. AI rookie / 포트폴리오 / 트위터 / 발표처럼 **최종 산출물이 시각 결과**인 도메인은 디폴트가 (b) 실제 1장. 도구 제공이 아니라 미리보기가 우선.
3. confirm 1줄 추가는 사용자에게 마찰이 아니라 시간 절약. 잘못된 방향으로 5분 작업한 후 정정받는 것보다 1줄 묻고 정확히 가는 게 항상 빠름.
