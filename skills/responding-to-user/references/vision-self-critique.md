# Vision-Driven Self-Critique for Visual Artifacts

When producing **non-text deliverables** (figures, diagrams, hero images, slide composites, charts), don't ship the first render. Use Vision_analyze on your own output to catch failures the user would otherwise catch — then patch and re-verify.

## When to apply

- Composite / hero / pitch figure for human review (competition, portfolio, slides)
- Generated diagram or infographic where layout balance matters
- Any PIL/matplotlib/SVG output before declaring "done"
- Chart where the user is going to make a decision based on it

Skip when: throwaway preview, internal-only debug image, user explicitly said "just make it, I'll review."

## Workflow

```
1. Render v1.
2. If image > 5MB or > 1920px wide:
     PIL.Image.thumbnail((1920,1920)) + .save(JPEG, quality=85)
   into a small companion file (Vision_analyze rejects >5MB base64).
3. Vision_analyze(image_url=small, question=critical-eval-prompt).
4. Read the critique. Categorize issues:
     - critical (kills impact / misleads viewer)  -> must fix
     - cosmetic (nice to have)                    -> defer
     - placeholder-only (resolves when real asset arrives) -> note + skip
5. Patch SKILL.md / script. Re-render v2. Re-analyze if critical issues touched layout.
6. Stop when no critical issues remain. Report fixes + remaining placeholder-only items to user.
```

## Critique prompt template

Don't ask "is it good?" — vision will be sycophantic. Force critical evaluation:

```
This is a [purpose] for [audience].
Evaluate: (1) [specific concern A] (2) [specific concern B]
(3) [specific concern C]. Be honest and critical. List issues in
priority order.
```

Examples that worked this session:

- "Is the layout clean? Is text legible? Does the right-side smoke
  asset look impactful and convincing as VFX output? Any issues with
  composition, contrast, or visual hierarchy that would hurt impact?
  Be honest and critical."

- "Verify: (1) Korean strings in JSON readable now? (2) Overall
  visual hierarchy/balance issues remaining?"

## Pitfalls

- **Tofu boxes (□) for non-ASCII**: PIL falls back silently. Vision will catch them. Common offenders on macOS:
  - Korean (Hangul): falls back if Helvetica/JetBrains Mono used. Fix: load `/System/Library/Fonts/AppleSDGothicNeo.ttc` and inline-switch fonts per character (see `is_korean()` pattern in `~/.hermes/scripts/ai_rookie_hero_dual.py`).
  - Circled digits ①②③: Helvetica missing them. Fix: replace with `#1 #2` or `(1) (2)`.
  - Em dash —: usually OK on macOS but check.
  - Emoji: never assume — most monospace fonts lack them.

- **Font fallback per-token, not per-line**: when JSON has English keys + Korean values on same line, you must switch fonts mid-string. Build a `draw_colored_line(tokens, fnt_en, fnt_ko)` helper that splits each token into runs of Korean / non-Korean and draws each run with the appropriate font, advancing x-cursor.

- **Vision 5MB limit on 4K outputs**: 3840×1646 PNG is ~5.5MB base64 → rejected. Always make a thumbnail companion `~1920px JPEG q=85` for vision calls. Keep the 4K original for delivery.

- **One-shot critique = false confidence**: vision often only catches 60-70% of issues per call. Run it again after major patches — second pass reveals issues hidden by the first pass's dominant problem.

- **Treating vision as oracle**: vision can be wrong about subjective taste ("middle column dominates") — weight critical/factual issues (tofu, clipped text, mislabeling) heavily, weight aesthetic critiques less. The user is the final aesthetic judge.

## Honest framing for external-tool outputs

When the visual deliverable contains an asset generated by an **external tool** (Midjourney, Nano Banana, Blender, EmberGen, etc.), the figure must label that asset honestly. Mythrill's pitch-assets convention:

- INPUT panel: real prompt
- LLM #1 OUTPUT panel: real validated JSON (verified component)
- Render panel: label as "TARGET CONCEPT RENDER" or "REFERENCE / NORTH STAR (external)" — NEVER "single take, zero manual edit" or "[your-tool] generated" if it isn't.
- Add a visible disclaimer chip on the asset panel: "NOT actual solver output — external concept reference."

A judge spotting Midjourney style on a "Mythrill MPM simulation output" label is unrecoverable. Honesty wins.

Domain rule (Mythrill specifically): see `~/.hermes/wiki/entities/mythrill-pitch-assets.md` "정직 프레임" — verified vs in-development components must be visually separated in any pitch figure.
